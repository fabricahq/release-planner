## ⬆️ Improvements

### Release notes focus on what your readers care about

Your agent now writes release notes about what your readers get: what they can now do, what works better, and what they have to change. It leaves out how each change was built, keeping a technical detail only when readers need it to see the value or to act, such as a command to run or a setting to change. If your own release notes style asks for more detail, the agent keeps it. (#15)

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/fabricahq/release-planner/v0.3.1/install.sh | sh -s -- --version v0.3.1
```

Then set `version: v0.3.1` in `.release-planner/config.yml`, run `release-planner install`, and commit the result.
