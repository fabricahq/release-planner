## ✨ New Features

### Release notes are checked before you merge

Release Planner now checks release notes against a set of rules. This applies in two main scenarios:

1. When your agent drafts release notes, it checks the draft against the rules and immediately repairs any issues.
2. When you, dear human, customize release notes and violate a rule, you will receive a warning, but can choose to ignore.

There are currently six rules. You can list them with `release-planner validate --rules`, and turn any of them off in `.release-planner/config.yml`:

```yaml
release-notes-rules:
  no-long-heading: off
```

See [release notes rules](https://release-planner.fabricahq.com/customize/release-notes-style/#release-notes-rules) for what each one checks. (#13)

## ⬆️ Improvements

### Cleaner release notes

Your agent now writes the whole notes file in one pass, instead of splicing text around a generated draft, which previously caused bizarre-looking release notes. When you ask for changes, it edits the notes in place, so your own edits are kept. (#13)

### Also in this release

- Release notes no longer open with a summary, unless your release notes style asks for one. (#13)
- If your release pull request merges in `main` to pick up newer changes, the notes still list the right pull requests. (#13)

## ⛓️‍💥 Breaking Changes

### Three config keys are renamed

These keys in `.release-planner/config.yml` are renamed so each says what it's for. Release Planner rejects the old names, so until you rename them, `install`, `inventory`, `validate`, and the Release workflow fail with an unknown-field error. (#13)

| Before | After |
| --- | --- |
| `validate:` | `release-checks:` |
| `notes-dir:` | `release-notes-dir:` |
| `branch:` | `release-branch:` |

### `plan` is now `validate`, and `draft` is gone

`release-planner plan` is renamed `validate`, with the same flags and output, and `release-planner draft` is removed; your agent writes the notes from `inventory` instead. The Release workflow's jobs are renamed to match: `plan` becomes `validate`, and `validate` becomes `release-checks`. If a script calls `plan` or `draft`, or a branch ruleset requires a check named `plan` or `validate`, update it, or the script fails and the ruleset waits for a check that never runs. (#13)

### Upgrade steps

1. Install v0.3.0:

   ```sh
   curl -fsSL https://raw.githubusercontent.com/fabricahq/release-planner/v0.3.0/install.sh | sh -s -- --version v0.3.0
   ```

2. Set `version: v0.3.0` in `.release-planner/config.yml`, and rename any of `validate:`, `notes-dir:`, and `branch:` it uses to `release-checks:`, `release-notes-dir:`, and `release-branch:`.
3. Replace `plan` with `validate` in any script that runs Release Planner, and remove any use of `draft`.
4. If a branch ruleset or branch protection rule requires one of the Release workflow's checks, update its name: `plan` is now `validate`, and `validate` is now `release-checks`.
5. Run `release-planner install` to update your Release workflow, agent guide, and release skill, then commit everything in one pull request.
